# Development

## Environment

Use Node.js 22.13+ (Node 24 is suitable) and npm. For Android local builds, install Android Studio with a current Android SDK and configure `ANDROID_HOME`/`ANDROID_SDK_ROOT`; attach an emulator or device. iOS builds require macOS and Xcode. The Expo managed workflow and config plugins are used; native projects are generated by Expo when a local native build is requested.

## Environment variables

Copy `.env.example` to `.env`. Set `EXPO_PUBLIC_SUPABASE_URL` and `EXPO_PUBLIC_SUPABASE_ANON_KEY` for account services. Set `EXPO_PUBLIC_TMDB_API_KEY` locally to enable TMDb catalog access. The TMDb API key is included in requests from the mobile client and is not a server-side secret; keep it out of source control and logs. `EXPO_PUBLIC_TMDB_BASE`, `EXPO_PUBLIC_TMDB_IMAGE`, and `EXPO_PUBLIC_ANILIST_ENDPOINT` have public defaults. Never use the Supabase service-role key in a mobile client. Expo only inlines `EXPO_PUBLIC_*` variables into application code.

There is deliberately **no** `EXPO_PUBLIC_TVDB_API_KEY`. Every `EXPO_PUBLIC_*` value is inlined into the shipped JS bundle and is trivially extractable, and a TVDB key grants full API access to whoever holds it. TVDB is reached only through the `tvdb-proxy` Edge Function, which keeps the key in a Supabase secret. See "TVDB catalog proxy" below.

## Data and guest mode

SQLite initializes on app startup before routes render. Guest session metadata is persisted separately from future collection data. Add schema changes as a new numbered migration; do not edit a migration after it has shipped. Keep SQL in data-layer code and preserve guest data when adding account migration.

## Supabase accounts and sync

Set `EXPO_PUBLIC_SUPABASE_URL` and `EXPO_PUBLIC_SUPABASE_ANON_KEY` in a local `.env`. These are the public client URL and anon/publishable key only. Never add a service-role key, database password, or JWT secret to the Expo app or `.env.example`.

Apply the versioned cloud migration using the Supabase CLI from a trusted development machine after linking the intended project (`supabase link --project-ref <project-ref>`, then `supabase db push`). Review `supabase/migrations/202610060001_watch_state.sql` first. This repository does not include the Supabase CLI, and the mobile app does not apply schema changes.

Sign-up and sign-in are available from More. If email confirmation is enabled, confirm the address and then sign in. Guest watch-state stays in SQLite and is merged at first authenticated sync. SQLite remains the runtime source of truth and the app never waits for the network for local watch-state operations. Mutations enter a durable outbox; a debounced background scheduler (`src/features/sync/autoSync.ts`) reuses `SyncService` to sync automatically after local mutations, sign-in/session restore, app foreground (15s cooldown), and offline → online transitions via `@react-native-community/netinfo`. Manual Sync now remains as a fallback. Conflict resolution compares UTC timestamps; newer state wins, and timestamp ties favor the local mutation. Removals and unwatches use tombstones. Automatic sync failures stay quiet (status store only); manual sync surfaces explicit feedback.

Sign-out preserves local state and pending changes. To prevent cross-account data transfer, a device library binds to the first account that syncs; another account is refused on that installation. Use a separate app data profile/device for a different account. Do not clear app data to troubleshoot before deciding what to do with the local library.

To reset a disposable development emulator safely, wait until More shows Synced, then clear app data through Android Settings. This removes that installation's SQLite database and persisted auth session; it does not delete cloud records. Jest uses mocked repositories and does not call Supabase.

Watchlist, watched, and episode state remain fully usable offline behind a subtle offline banner; the `AppErrorBoundary` in `app/_layout.tsx` catches unexpected rendering failures with a recovery screen that never deletes local data. Catalog metadata is cached with stale-while-refresh TanStack Query settings (`src/features/catalog/hooks.ts`); user watch state is never cached outside SQLite. Wide screens constrain content to a readable max width (`src/theme/responsive.ts`).

Home discovery (Trending Now, Recently Released) reads live TMDb list endpoints (`trending/movie|tv/week`, `movie/now_playing`, `tv/on_the_air`) plus AniList trending anime through `RemoteCatalogRepository.getTrending/getRecentlyReleased`; results cache in TanStack Query and refresh automatically as providers update. Favorites sync like other watch state via the `favorite` outbox entity and Supabase `favorite_entries` (`supabase/migrations/202610060003_favorites.sql`, applied with `supabase db push`). Custom lists and viewing history are local-only in this phase: lists persist in SQLite (`custom_lists`, `custom_list_items`, migration v7) without cloud sync, and history derives from actual movie/episode watch timestamps. User ratings and rewatch counts sync like other watch state (`user_ratings` table, `rating` outbox entity, migration v8; Supabase `202610060004_ratings_rewatch.sql`).

## Google sign-in and delete-account backend

Google OAuth (Supabase dashboard, one time): Authentication -> Providers -> Google -> enable with your OAuth client ID/secret, then URL Configuration -> Redirect URLs -> add the dev redirect (Expo Go prints it; typically your LAN exp:// URL plus uth/callback) and watchlater://auth/callback for builds. No app code changes needed after that. Redirect picking is automatic: dev sessions (Expo Go / dev client on Metro) use the live exp:// session URL so the browser returns to the running app; production builds use watchlater://auth/callback. If Metro restarts on a different port, add that exact exp:// URL to the Supabase redirect list.

Delete-account edge function: supabase functions deploy delete-account after supabase secrets set SERVICE_ROLE_KEY=... (the CLI reserves the SUPABASE_ prefix; SUPABASE_URL and SUPABASE_ANON_KEY are platform-injected). It deletes the auth user with the service-role key, and every user table cascades from auth.users, so the whole server-side wipe follows from that one call. The client resolves a live access token and runs this step FIRST: if it cannot run, nothing is destroyed anywhere and the error is surfaced, so data and the sign-in are always deleted together or not at all. Only once the account is gone does it sweep leftover rows, clear query caches, wipe the local database, cancel reminders and sign out.


## Global Hits reports and scheduler

Published rankings live in public.global_hit_reports (migrations 202610110002/03: public SELECT, service-role writes). Generation is the generate-global-hits edge function (TMDB Discover, methodology tmdb-popularity-v1, 20 movies + 20 series per report, idempotent: published rows are never rewritten).

Function secrets: TMDB_API_KEY (TMDB v3 key) and HITS_ADMIN_KEY (manual-trigger password). The app never calls the function and never sees either value.

Scheduling (manual dashboard step, NOT done automatically): Edge Functions -> generate-global-hits -> add a daily cron trigger (e.g. 5 0 * * * UTC) that POSTs an empty JSON body with header x-hits-admin-key set to the admin key. The function publishes the last completed month (and last year each January) only when missing, so overlapping runs are safe. December 31 publishes nothing by design: the yearly final generates on January 1 once the data is complete.

Manual trigger: POST https://<ref>.supabase.co/functions/v1/generate-global-hits with apikey header + x-hits-admin-key and body {periodType, periodKey} (add dryRun:true to compute without publishing).


## IMDb Top 250 pipeline

Weekly snapshot in public.imdb_ratings (migration 202610110004: public SELECT, service-role writes). The .github/workflows/imdb-ratings.yml Action (Sundays 03:00 UTC, stdlib-only Python, manual Run workflow button available) downloads official IMDb dumps, ranks with IMDb's own weighted formula (25k-vote minimum, adult excluded), maps the top candidates to TMDB ids via /find, and upserts 250 movies + 250 series with stable ranks. Refuses to publish partial lists under 150 titles per side.

Repo secrets required (GitHub Settings -> Secrets -> Actions, manual one-time step): SUPABASE_URL, SUPABASE_SERVICE_ROLE_KEY, TMDB_API_KEY. The app reads the table with the anon key and never sees these values. First run: Actions tab -> imdb-ratings -> Run workflow, then check More -> IMDb Top 250 in the app.

 The same run also snapshots recent releases (current + previous year, 1000+ votes, unranked rows) so detail screens and Global Hits cards can show IMDb scores for fresh titles.


## TVDB catalog proxy

TVDB is reached only through the `tvdb-proxy` edge function (`supabase/functions/tvdb-proxy/index.ts`). The mobile client POSTs `{ path, params }` to `/functions/v1/tvdb-proxy`; the function validates the path against an allowlist of read-only catalog routes, performs TVDB login and caches the bearer token server-side, and forwards the request. The TVDB API key never enters the JS bundle, and TVDB's session lifecycle is entirely off the client.

The client reads only `EXPO_PUBLIC_SUPABASE_URL` and `EXPO_PUBLIC_SUPABASE_ANON_KEY`. Catalog search works in guest mode, so the function accepts the public anon key and does not require a signed-in user.

One-time deploy (manual step, NOT done automatically):

```sh
supabase functions deploy tvdb-proxy
supabase secrets set TVDB_API_KEY=<your tvdb v4 key>
```

Rotate the TVDB key before deploying: any build produced while `EXPO_PUBLIC_TVDB_API_KEY` existed carried the old value in plaintext, so treat it as exposed. After rotation the old value is worthless.

Abuse control is layered because the anon key ships in the app bundle and is therefore public: Supabase still requires a valid JWT, the path allowlist caps the surface to read-only lookups (no writes, no SSRF), and a per-IP sliding window (60 requests/minute) throttles quota burn. This is a throttle rather than a hard quota, since Deno isolates hold no shared state.

If TVDB detail screens start failing with `configuration` errors, confirm the function is deployed and the secret is set. If they fail with `rate_limited`/429, the per-IP window is tripping and the limits in `tvdb-proxy/index.ts` need raising.


## Creator Studio

Creator Studio lives behind More → Create → Creator Studio (`/creator`). Drafts are device-local (SQLite, no account); creation, editing, export, and sharing all work offline. There is no sign-in gate anywhere in the studio.

Cloud drafts were removed: the earlier `supabase/migrations/202610180001_creator_projects.sql` migration stays in the repo (the shipped SQL contract is asserted by `tests/supabaseSecurity.test.ts`, and projects that already applied it keep the table), but the app never queries `creator_projects` — no setup step is required, and new environments can skip it.

Native dependencies: `react-native-view-shot` (slide capture), `expo-media-library` (gallery save; configured in `app.json` with `savePhotosPermission` and the `photo` granular permission), `expo-sharing`, and `expo-clipboard`. Because `app.json` changed, rebuild the dev client (`npx expo prebuild --clean`, then `npx expo run:android`) or reinstall it; Expo Go cannot load `react-native-view-shot`.

Manual export verification (no emulator is assumed): open a layout with a real poster, choose Export → Save to gallery, grant Photos access when prompted, then confirm the saved file is a 1080×1350 PNG, text is sharp (3× capture of the 360×450 canvas), and no editor chrome is baked in. Repeat after denying permission (the dialog offers Open settings), with a broken poster URL (gradient fallback, export still succeeds), and for a multi-slide carousel that mixes layouts (cover → stacked rows → follow card; files save in slide order). Share opens the system sheet with one PNG; carousels intentionally share the first slide and tell the user to save all slides for ordered attachment.

Tests: `tests/creatorStudio.test.ts` covers validation (v2 payloads with per-slide layouts and branding), layout registry, title snapshots, slide distribution, captions, slide text, export planning, the reducer, and seed mapping; `tests/creatorEditor.test.tsx` renders every layout with empty slides, the stacked/cover/promo layouts with real metadata, and per-slide layout overrides in both themes; `tests/supabaseSecurity.test.ts` asserts the RLS, grants, and trigger contract of the legacy migration.

## Android release builds

`android/` is gitignored and regenerated by `expo prebuild`, so every native setting lives in config plugins under `plugins/` rather than in the generated tree:

- `withNotifeeRepo.js` — registers Notifee's bundled Maven repo on the root project. `@notifee/react-native` resolves `app.notifee:core` from an AAR it ships in its own package; that artifact is published to no public repository, so without this the build fails with "Could not find any matches for app.notifee:core".
- `withReleaseSigning.js` — adds a `release` signing config and points the release buildType at it. Expo's template signs release builds with the Android debug keystore, a well-known public key that Play Console rejects. Credentials resolve from `ANDROID_KEYSTORE_*` env vars (EAS) first, then `credentials/keystore.properties` (local builds); with neither present it warns and keeps debug signing so prebuild still succeeds for contributors without a key.
- `expo-build-properties` (in `app.json`) — enables `minifyEnabled` and `shrinkResources` for release and supplies ProGuard keep rules for the native libraries in use (Reanimated, Worklets, Notifee, SVG, gesture handler, screens, safe-area context, FCM).

The upload keystore lives in `credentials/` (outside the generated `android/` tree, because prebuild would delete it) and is gitignored along with `credentials.json`, which holds plaintext secrets. Back up `credentials/upload-keystore.jks` and its password: losing both means the shipped app can never be updated again. Upload-key SHA1 is `83:D8:72:35:AA:6A:36:42:65:F6:FC:31:C6:45:AF:E6:11:2D:B2:9A` — enroll in Play App Signing so Google holds the app-signing key and only the upload key needs protecting.

R8 minification changes runtime behavior by stripping unreachable code, so after enabling or updating the keep rules, verify a release build actually boots and navigates — not just that Gradle reports success. Build with `cd android && ./gradlew :app:bundleRelease`.
